# Product Owner/PM - Требования к фиче /players

**Роль:** PM
**На основе:** docs/bmad/01-analyst/analysis.md
**Дата:** 2026-11-02

## User Story
Как участник комнаты, я хочу видеть список игроков в комнате, чтобы знать состав перед началом раунда.

## Acceptance Criteria
- [ ] AC1: Команда /players доступна всем участникам комнаты
- [ ] AC2: При вызове из комнаты бот выводит список всех участников с их именами
- [ ] AC3: Если пользователь не состоит ни в одной комнате, бот сообщает об этом
- [ ] AC4: Создатель комнаты отображается в списке так же, как и остальные
- [ ] AC5: Список отображается в читаемом формате

## Функциональные требования
FR-1: Получить текущую комнату пользователя (как в /room)
FR-2: Получить всех участников комнаты из room_members
FR-3: Для каждого участника получить информацию из users (full_name, username)
FR-4: Вывести отформатированный список

## Нефункциональные требования
NFR-1: Минимальная нагрузка на БД - один/два запроса
NFR-2: Сохранение стиля кода проекта
NFR-3: Без изменения существующих таблиц БД

## Scope
**В scope:** Добавить хендлер /players, добавить команду в /room меню (опционально), обновить commands.txt
**Не в scope:** Сортировка по ролям, счётчики, аватары

## Риски
- Низкий риск. Использует существующие таблицы
